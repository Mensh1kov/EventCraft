# Фича: Шаблоны мероприятий

## Концепция

**Шаблон = структура мероприятия** — то, что одинаково для всех событий одного типа.
**Форма создания проекта = конкретные детали** — то, что вводится каждый раз заново.

При создании нового мероприятия пользователь выбирает шаблон → система создаёт
проект с готовыми статусами, метками и типовыми задачами. Бюджет, дата и название
всегда вводятся вручную.

---

## Пользовательские истории

**Как организатор мероприятий**, я хочу:

- **Создать мероприятие из шаблона** — чтобы не настраивать статусы, метки и список задач каждый раз с нуля, а выбрать готовую структуру и сразу перейти к работе.

- **Выбрать шаблон по категории и названию** — чтобы быстро найти нужный среди всех шаблонов воркспейса, не листая весь список.

- **Посмотреть задачи внутри шаблона до создания мероприятия** — чтобы убедиться, что шаблон подходит, и увидеть ориентировочную стоимость по каждой задаче.

- **Получить предзаполненный бюджет при создании мероприятия** — чтобы не считать вручную: система суммирует типовые стоимости задач из шаблона и подставляет итог, я корректирую если нужно.

- **Сохранить существующее мероприятие как шаблон** — чтобы зафиксировать удачную структуру и переиспользовать её в будущем.

- **Создать мероприятие прямо со страницы шаблона** — чтобы не возвращаться на главную: открыл шаблон, посмотрел задачи, нажал "Создать мероприятие".

**Как администратор воркспейса**, я хочу:

- **Создавать и редактировать шаблоны:**
  - _Основное_ — название, описание, emoji, категория
  - _Статусы_ — добавить / удалить / переименовать, задать цвет, группу (backlog / unstarted / started / completed / cancelled), порядок через drag-and-drop
  - _Метки_ — добавить / удалить / переименовать, задать цвет
  - _Задачи_ — добавить / удалить / переименовать, задать приоритет, описание, метку, ориентировочную стоимость, порядок

- **Присваивать шаблону категорию** — чтобы организаторы могли быстро фильтровать шаблоны по типу мероприятия.

- **Видеть, сколько раз использован шаблон** — чтобы понимать, какие шаблоны востребованы, а какие можно удалить.

### Редактор шаблона

Четыре секции:

1. **Основное** — название, описание, emoji, категория
2. **Статусы** — список с drag-and-drop, цвет, группа
3. **Метки** — список, цвет
4. **Типовые задачи** — список: название, описание, приоритет, метка, ориентировочная стоимость, порядок

## Модель данных

### Backend

**`ProjectTemplate`** (уровень воркспейса):

| Поле          | Тип                                                                           |
| ------------- | ----------------------------------------------------------------------------- |
| `workspace`   | FK → Workspace                                                                |
| `name`        | CharField(255)                                                                |
| `description` | TextField, blank                                                              |
| `emoji`       | CharField(255), nullable                                                      |
| `category`    | CharField(50), choices, default=`other`                                       |
| `usage_count` | PositiveIntegerField, default=0 — инкрементируется при каждом вызове `apply/` |

Допустимые значения `category`:

```python
CATEGORY_CHOICES = [
    ("corporate",    "Корпоратив"),
    ("conference",   "Конференция"),
    ("teambuilding", "Тимбилдинг"),
    ("training",     "Обучение"),
    ("other",        "Другое"),
]
```

**`TemplateState`**:

| Поле         | Тип                                                       |
| ------------ | --------------------------------------------------------- |
| `template`   | FK → ProjectTemplate                                      |
| `name`       | CharField(255)                                            |
| `color`      | CharField(255)                                            |
| `group`      | CharField (backlog/unstarted/started/completed/cancelled) |
| `sequence`   | FloatField                                                |
| `is_default` | BooleanField                                              |

**`TemplateLabel`**:

| Поле       | Тип                  |
| ---------- | -------------------- |
| `template` | FK → ProjectTemplate |
| `name`     | CharField(255)       |
| `color`    | CharField(255)       |

**`TemplateTask`**:

| Поле             | Тип                                                     |
| ---------------- | ------------------------------------------------------- |
| `template`       | FK → ProjectTemplate                                    |
| `title`          | CharField(255)                                          |
| `description`    | TextField, blank                                        |
| `priority`       | CharField (urgent/high/medium/low/none)                 |
| `label_name`     | CharField(255), nullable — имя метки из TemplateLabel   |
| `sequence`       | FloatField                                              |
| `estimated_cost` | DecimalField(10,2), nullable — типовая стоимость задачи |

Сумма `estimated_cost` всех задач шаблона используется для предзаполнения поля бюджета на Шаге 2 создания мероприятия. Пользователь может скорректировать итоговую сумму вручную.

**`apps/api/plane/db/migrations/0124_project_templates.py`** — миграция.

### 2. Backend — сериализаторы

**`apps/api/plane/app/serializers/project_template.py`** — новый файл:

- `TemplateStateSerializer`
- `TemplateLabelSerializer`
- `TemplateTaskSerializer`
- `ProjectTemplateSerializer` (nested — включает все три выше)

### 3. Backend — ViewSet и URLs

**Права доступа:** любой участник воркспейса (`WorkspaceMemberPermission`) — создание, редактирование, удаление, применение шаблонов.

**Эндпоинты:**

```
GET/POST         /api/workspaces/{slug}/project-templates/
GET/PATCH/DELETE /api/workspaces/{slug}/project-templates/{template_id}/
POST             /api/workspaces/{slug}/project-templates/{template_id}/apply/
POST             /api/workspaces/{slug}/projects/{project_id}/save-as-template/
```

**`apply/`** — создаёт проект из шаблона:

1. Принимает `name`, `event_date`, `budget_total` (бюджет всегда передаётся с фронта — либо введённый пользователем, либо предзаполненная сумма `estimated_cost`)
2. Создаёт `Project` с переданными параметрами
3. Удаляет дефолтные State объекты проекта
4. Создаёт State из `TemplateState[]`
5. Создаёт Label из `TemplateLabel[]`
6. Создаёт Issue из `TemplateTask[]` (с дефолтным статусом)
7. Инкрементирует `usage_count` шаблона

**`save-as-template/`** — создаёт шаблон из существующего проекта:

1. Читает States, Labels, Issues проекта
2. Создаёт ProjectTemplate с вложенными объектами
3. Очищает личные данные (даты, исполнители)

### 6. Frontend — фильтрация шаблонов

Фильтрация на клиенте (API отдаёт все шаблоны воркспейса, их обычно немного).

**Состояние:** `activeCategory: string | null` + `searchQuery: string` в локальном стейте компонента выбора шаблона.

**Логика:** шаблоны фильтруются по `category === activeCategory` (если выбрана) и по вхождению `searchQuery` в `name` или `description` (case-insensitive).

**Компоненты:**

- `template-category-filter.tsx` — чипсы категорий (Все / Корпоратив / ...)
- `template-search.tsx` — поле поиска

### 8. Frontend — выбор шаблона при создании проекта

**`apps/web/ce/components/projects/create/root.tsx`** — обновить форму создания:

1. Добавить шаг выбора шаблона перед основной формой
2. Если выбран шаблон — показать превью (кол-во статусов, меток, задач)

### 10. AI-ассистент

Ассистент получает три новых инструмента для работы с шаблонами.

**`list_templates(category?)`**
Возвращает список шаблонов воркспейса (опционально — по категории). Используется чтобы предложить подходящий шаблон или уточнить выбор.

**`create_event_from_template(template_id, name, event_date, budget?)`**
Создаёт мероприятие из шаблона. Если `budget` не передан — подставляется сумма `estimated_cost` задач шаблона. Вызывает эндпоинт `apply/`.

**`save_project_as_template(project_id, name, category)`**
Сохраняет существующее мероприятие как шаблон. Вызывает `save-as-template/`.

**Уточнение параметров:**

- `event_date` — **обязательный**: если не указана, ассистент спрашивает "На какую дату запланировать?" перед созданием.
- `budget` — **необязательный**: если не указан, подставляется сумма `estimated_cost` задач шаблона; ассистент сообщает об этом: "Бюджет подставлен из шаблона — 135 000 ₽, можете изменить".

**Флоу создания мероприятия:**

```
Пользователь: "Создай тимбилдинг в июле"
        ↓
Ассистент: list_templates(category="teambuilding")
        ↓
Нашлись шаблоны → сообщает:
  "Нашёл 2 шаблона:
   • Тимбилдинг-лайт — 8 задач, ~40 000 ₽
   • Тимбилдинг-выезд — 15 задач, ~120 000 ₽
   Использовать один из них?"
        ↓
┌─────────────────────┬──────────────────────────────┐
│ Пользователь выбрал │ Пользователь отказался       │
│ шаблон              │ ("нет, создай сам")           │
├─────────────────────┼──────────────────────────────┤
│ Уточняет дату если  │ Создаёт новый пустой проект  │
│ не указана →        │ и генерирует задачи сам,      │
│ create_event_from   │ исходя из запроса             │
│ _template(...)      │                              │
└─────────────────────┴──────────────────────────────┘
```

Шаблоны не найдены → ассистент сразу переходит к созданию нового проекта с задачами.

**Сценарий "Сохранить как шаблон":**

`save_project_as_template(...)` — ассистент предлагает название и категорию на основе текущего проекта, пользователь подтверждает.

После `create_event_from_template` ассистент делает рефетч списка проектов — аналогично существующему паттерну рефетча задач после действий AI.
